## 零、Usage及Configuration

1. 将脚本添加至调度器。
2. 右键点击脚本以修改 JS 自定义Configuration。
-  **卡时间模式**
   - “Treasure Hoarder/愚人众/鳄鱼Raw MeatFriendship”：均为做Friendship任务获取收益，等昨天的Investigating点CD结束。
   - “干等卡时间”：原地Dazed，等昨天的Investigating点CD结束。
   - “不卡时间AB交替运行”：立刻富A富B交替运行，不需要等24小时CD，富A富BRoute之间要等12小时CD。
-  **是否启用激活Route**：启用后将花费一段时间先四处传送激活Artifact EXPInvestigating点，可以用于缩短间隔（提高A线比例，从而提高总收益）/降低因为后续Route卡死导致运行时间波动引起第二天Artifact EXP点位未刷新/启用后当日运行完激活Route后跑Artifact EXP过程中如果卡死可以当日直接重跑，不会导致少跑a线。
-  **使用老abeRoute**：勾选后将替换为使用老abe的Route，收益会下降。
-  **Friendship任务最低运行次数**：填写0~50次（上限），前10次收益最高。捡完Artifact EXP会回来打完未完成的次数。
-  **账户名称**：**单Account无需更改。** 多Account使用时建多个Configuration组，一个Account使用一个Configuration组，填入游戏Account名称（自己取名），就可以按各自名称Recording运行信息。
-  **Friendship队名称**：改成自己刷Friendship的队伍名字，该队伍也将用于清理Artifact EXPRoute上的Common Mobs，**需要自行匹配Combat策略。**
-  **Artifact EXP队名称**：改成自己捡Artifact EXP的队伍名字。建议使用迪西雅或e启动奶妈作为行走位，如果需要Configuration生存位，建议与行走位相同。建议携带：迪西雅（耐肘王，提供移速加成），Kaedehara Kazuha（Route中有ConfigurationKaedehara Kazuha吸取Artifact EXP，可提高拾取率）
-  **最短时间间隔**：比昨天延后（默认）5分钟Starting Up捡Artifact EXP。如果启用了激活Route，可以降低至1-2分钟。
-  **卡时间时间段**：在此时间段内，会每天延后1次时间间隔来跑富ARoute。若时间超出则立刻运行富BRoute，第二天则会回到。
3. 一定要正确SettingsFriendship队和Artifact EXP队的名称。
4. 根据Friendship队CharacterConfiguration，调整Combat超时Settings。
   
## Precautions / Notes

1. 对于运行时间和Route的Recording依赖本地文件的读写，直接更新js会导致丢失Recording影响收益，建议更新js前先备份js文件夹中的records文件夹，更新后覆盖。
2. Route和abe略有差异，第一次运行时收益下降是正常现象，第二天即可恢复正常，或者第一次在晚于前一天运行abe的时间Starting Up运行本js也可解决。
3. Artifact EXPRoute出现卡死、跳崖等问题请找 @汐 ，Treasure HoarderFriendship部分出现问题请找 @秋云。
4. 默认Configuration下将在4：05-4：45卡时间，如果你常用的启动时间Nope, Not In这个时间段，请在js自定义Configuration中调节，建议总时长不超过40分钟，否则会在Treasure Hoarder等Friendship全部运行结束都不能等到时间的话会Starting Up干等。
5. 务必在js自定义Configuration中填写合适的Artifact EXP队伍与Friendship队伍名称，运行过程中会Auto Switch，要求正确Configuration生存位，行走位，Combat策略（用于FriendshipCombat）等。同时要确保在Configuration组中启用“允许在JsScript中使用”和“覆盖JS中的Auto CombatConfiguration”。
6. 还在测试中可能存在bug，bug反馈和建议可以在频道中Question，或联系相关Author。
7. 本脚本不支持断点续跑，如果你需要相关Features，Guide / Instructions你不适合使用本脚本，请移步abe。
8. 清怪和激活时不会拾取，属于正常现象。

## 二、Investigating点机制与刷新CD

### **误区**  
❌ *错误认知*：很多人误以为Investigating点的 **24小时CD** 是从 **按FInvestigating** 时Starting Up计算的。  

✅ **实际机制**：
-  **游戏程序只会加载以玩家为圆心，固定半径内地图资源，Investigating点也在此时被激活，产生发光特效（CD倒计时未结束不会被激活）即数据出现在内存中时CD倒计时Auto Starting Up。**    
-  **每天4点刷新可互动的Investigating点上限100个，Investigating满上限后，进入未加载区域，Investigating点将不再被激活。** 在最后范围内，已经激活的Investigating点不会消失，可以继续Investigating。  
- **与是否Investigating/拾取无关**！即使不Investigating或下线，CD仍会继续倒计时。 例：今天你10点路过某区域，24小时CD的Investigating点Starting Up发光随后离开，15点再回来拾取Investigating点。明天此Investigating点会在10点CD倒计时结束，可以再次拾取。  
- **单日多次加载无效**：若在CD未结束前重复加载Investigating点（无论拾取与否），都不会重置计时。

## 四、Path结构

 **-1激活**：提前加载触发CD倒计时，后续可自由安排时间拾取，避免“现用现触发”的等待问题，无需WorriedCD同步问题     
 **00准备**：部分优质富点有Common Mobs镇守，清除以后才按Path顺序拾取，此时不拾取Investigating点!少数点位需要提前转变为发光点，不拾取Investigating点!   
 **01Normal**：至多98个Investigating点   
 **02Cleanup**：附近区域超出100以外的Investigating点   
 **03额外**：不受满上限影响消失，又叫超限点   


## 五、周循环方案对比

### 1. 富6A1B方案

- **执行方式**：
  - 连续6天跑富ARoute（富A与富A间隔≥24H+5min）
  - 第7天跑富BRoute（与富A间隔≥12H+5min）
- **周总收益**：
  - 经验：6×98,469 + 83,160 = 673,974 EXP
  - Mora：6×22,600 + 21,000 = 156,600
- **周总耗时**：6×69 + 53 = 467分钟（约7.78小时）

### 2. 富1A1B方案

- **执行方式**：
  - 每天交替跑富A和富BRoute（间隔≥12H+5min）
- **周总收益**：
  - 经验：3.5×(98,469+83,160) = 635,701 EXP
  - Mora：3.5×(22,600+21,000) = 152,600
- **周总耗时**：3.5×(69+53) = 427分钟（约7.11小时）

### 3. ABE 1A1B方案（基准）

- **执行方式**：
  - 每天交替跑ABE A线和B线（点位不重叠，无间隔要求）
- **周总收益**：
  - 经验：3.5×(77,742+77,868) = 544,677 EXP
  - Mora：3.5×(6,600+6,800) = 46,900
- **周总耗时**：3.5×(41+43) = 294分钟（约4.9小时）

## 六、队伍Configuration
- **根据自己CPUConfiguration选择合适的移速**：电脑性能较差以至于收益远不如及格线时，降低队伍移速（使用较矮小的体型，不使用双风，Lost Prayer to the Sacred Winds，迪西雅天赋等）。
- **行走位：优先Dehya;或Furina等 E启动奶**
- **The BellDehya**：耐肘王/白天6-18点移速+10%(Path内置调时间到白天,全程100%吃满天赋)
- **Kaedehara Kazuha：建议携带，Path内配有E吸Artifact EXP策略(不带不影响运行)**
- **双风BUFF**：移速+10% 体力消耗-15%


## 七、选择建议

1. **追求极限收益**：富nA1B方案（周经验13万+24%，周耗时多2.88小时）。
2. **想多收益又不想卡时间**：富1A1B方案（周经验9.6万+17.7%，周耗时多2.88小时）。
3. **希望方便随时启动就能用**：选择老abeRoute。


## 八、JS文件结构

1. **main.js**：负责核心业务逻辑，包括Friendship任务和Artifact EXPRoute的执行。
2. **manifest.json**：脚本Configuration文件，Recording基本信息和Settings。
3. **settings.json**：用户Configuration文件，用于SettingsFriendship队和Artifact EXP队的名称、任务间隔等参数。
4. **records**：运行Recording文件，用于存储运行信息。


## 九、Features特点

1. 完成Friendship任务。
2. 执行Artifact EXPRoute，Auto 计算时间并进行Route选择。
3. 可选择在Artifact EXPRoute结束后继续完成剩余的Friendship任务。
